# 0.48.6 批量部分提交漏转发补丁

## 根因与修复

0.48.5 的 `ServerIngressBatchRuntime.applyIngressBatchBodies` 在批量 Apply 返回错误时，将已经提交的消息前缀写入成功日志，直接返回成功数量给 RabbitMQ Consumer。Consumer 据此 ACK 前缀，但该错误分支跳过了后续 dispatch。因此主站已有数据，其他从站仍可能缺行；这些已 ACK 消息不会因后缀重试而重新转发。

数据库死锁是触发条件；真正导致缺行的是“已落库”被当成“已完成中继”。该缺陷也可能由其他批量中途错误触发，不限于死锁或批量 16。

0.48.6 将已提交前缀继续送入公共日志持久化和转发流程，只有完成所需转发才计入可 ACK 数量。前缀转发失败时，从该消息开始重新入队；尚未提交的后缀同样重试。错误批次的 dispatch_count 现在保留实际完成的转发数量。

不修改协议、规则 ID、显示名称、业务表或首次对齐证明，不新增迁移。安装包沿用 0.48.5 系统库升级入口，检查既有迁移并记录新应用版本。
