## 本轮功能

- `Edge1 <-> Server <-> EdgeN` 同表双向：明确完整成员、按真实库表/列/主键映射、中心串行协调复制，组PENDING/READY/ACTIVE证据防止未完成组提前启动。
- 中心非空向空Edge复制，或唯一非空Edge先复制到中心再分发；全空也建立边界。多个原有非空源拒绝合并或覆盖。
- 快照原始值上限256MiB、编码传输512MiB，单次复制15分钟，组协调一小时。中心源和边缘源均完成200MiB实传及后续真实增量短测；单行仍受1MiB编码帧限制。
- 稳定来源epoch，所有成员重放首次边界后的冲突版本及墓碑，覆盖顺序快照之间的新写入，避免后复制成员遗失版本历史。
- MCP新增`nodebridge_start_initial_alignment`、`nodebridge_initial_alignment_status`、`nodebridge_interrupt_initial_alignment`，再次start用于核验重试；普通stdio42工具、5资源。没有新增HTTP服务或审批体系。
- 既有规则页支持中心多成员选择、Edge单中心及三语阶段/确认；执行中禁改规则。受管Canal容量补丁将缓存/最大堆提高到至少512MiB/2GiB，不降低补丁读到的更大值。

## 升级与使用

1. 备份全部节点的配置、规则、配对清单和数据库。停止所有参与Agent，在原界面显式退出旧UI；安装器不会替操作员停止任意工作区副本。
2. 使用配置所属Windows账户安装同一版本。默认复用已有组件并保留配置；不跨机器或账户搬运DPAPI密文，不改变SSH登录身份。
3. 大快照前核对每台Canal的堆和未ACK缓存。复用/外部组件不会自动调参；已经运行的Canal须在维护窗口确认配置并显式重启。受管组件重装前也应备份自定义配置。
4. 按[首次全量指南](initial-alignment.md)配置完整成员与映射，并在所有节点通过UI、CLI或MCP分别确认执行。MCP保持各stdio会话并轮询；running、单对复制完成或unknown都不是完整组完成。
5. 全部节点completed后，再明确启动同步。中断不撤销提交，重试保留原证据；不能删系统表、版本、墓碑或手改ACTIVE来解除阻断。
