# 0.48.8 Windows 边缘账号配置复核

身份：review-ai。结论：现场报告的问题存在，Windows 批处理参数路径已本地复现；NB-ALIGNMENT-PERMISSIONS 重新打开。本轮不修改产品、不连接现场、不执行迁移或启动 Agent。

## 复现

本机 Windows 使用无害 `probe.bat` 替代 rabbitmqctl，只输出参数，不调用 RabbitMQ。通过当前源码 `rabbitmq.NewAdmin().EnsureServerEdgeUser` 的真实默认 runner 执行，结果与现场完全相同：

```text
set RabbitMQ permissions for nb-edge-001: The system cannot find the path specified.: exit status 255
```

- 同一文件、同一调用方式，权限参数 `.*` 成功。
- 改成 `^(server\.ingress\..*|amq\.default)$` 后失败，退出码 255。
- 在夹具中使用显式 `cmd.exe /d /s /c` 命令行并引用全部参数，同一正则完整到达批处理且退出 0。
- 复现源码、批处理与完整输出：`.cache/rabbit-bat-review-20260918/{main.go,probe.bat,result.txt}`。

`internal/installer/rabbitmq/admin.go` 的 `runCommand` 直接使用 `exec.CommandContext(ctx, name, args...)` 执行 `.bat`。当前参数未采用批处理所需引用规则，正则中的管道等字符进入 cmd 解析。该错误不是已证明的文件缺失，也不是 RabbitMQ 正则权限拒绝。夹具对照证明参数传递层缺陷；完整 rabbitmqctl 内部批处理链仍需修复后的 Windows 实测。

## 之前漏测的范围

单测注入自定义 Runner，仅核对参数及正则匹配；集成测试同样替换 Runner，经 Docker 在容器里执行 rabbitmqctl。它们证明了权限表达式的业务效果，没有覆盖 Windows `.bat` 默认 runner。因此之前将权限问题整体标记 closed 范围过大，不能将手工权限仍有效当成 MCP 成功。

## 数据保留语义

`internal/alignment/rebaseline.go` 会先把目标整表插入备份，再 DELETE 目标表，二者与准备收据同事务提交。之后以 Edge 快照重新对齐。108 独有行留在备份中，不会自动合并到活动业务表。现场报告对此判断正确。

用户此前已明确选择以 105 为准，不能说完全没有权威源选择。但如果同时要求 108 独有数据继续留在活动业务表，则本版流程不能满足该合并要求；仅有备份不等价于业务数据仍可正常查询。本轮未执行任何数据操作。
