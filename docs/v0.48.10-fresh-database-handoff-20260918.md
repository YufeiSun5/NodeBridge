## 原因与修复

全新安装还没有节点/MySQL 配置时，安装器按设计跳过系统库升级。随后用户配置 `scada_center` 等系统库，原界面只有连接测试，没有初始化入口；升级命令也直接连接指定库，因此缺库时出现 `Error 1049: Unknown database`，库存在但未迁移时会缺少系统表。

0.48.10 新增“同步配置 → 初始化系统库”。操作先保存当前表单，再运行 `upgrade-system -create-database`：以不指定数据库的连接创建配置中的系统库，再执行按节点角色选择的系统表迁移及索引升级。只有显式初始化才创建数据库，普通连接测试和 Agent 启动不隐式创建空库。系统库升级失败现在会向 stderr 输出脱敏后的具体原因，不再只返回退出码。

操作要求界面解锁、节点和 MySQL 配置完整、同步 Agent 停止以及建库/建表权限。CLI 与安装器升级共用迁移校验及 Agent 文件锁。只执行系统表迁移，不创建样例业务表、不删除数据、不自动启动同步。旧同步历史和业务库仍需按原迁移流程恢复；此功能不能替代数据迁移。

## 使用

1. 安装新版，打开“同步配置”，填写节点角色、节点 ID 与 MySQL 连接。
2. 停止同步，点击 **初始化系统库**，等待完成。
3. 点击“测试 MySQL”，再配置和检查业务表、RabbitMQ、CDC 及规则。旧机迁移还需恢复旧同步历史，不能将空系统库视为已恢复。

命令行等价操作：

```powershell
& 'C:\Program Files\NodeBridge\SyncAgent.exe' upgrade-system -config 'C:\ProgramData\NodeBridge\config.yaml' -create-database
```

## English

The configuration page now provides explicit system database initialization after saving settings. It creates the configured database and applies NodeBridge system migrations with the Agent stopped. Connection tests remain read-only. It does not restore business data or previous synchronization history, and does not start synchronization. Upgrade failures now include redacted diagnostic output.
