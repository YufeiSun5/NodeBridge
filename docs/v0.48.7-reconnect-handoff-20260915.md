# 0.48.7 RabbitMQ 自动重连补丁

## 根因

现场记录 `nodebridge-reconnect-20260915.md` 显示 0.48.5 发布器/下行通道持续报 AMQP 504，人工重启边缘 Agent 后积压补齐。读取源码确认：`runEdgeWorkers` / `runServerWorkers` 仅启动时构造 RabbitMQ Connection、Channel、Publisher；工作循环只重试 RunOnce。Publisher 在发送结果不确定或确认通道关闭后被永久标记失效，但调用者没有重建逻辑。因此进程仍运行，上传/下发却无限重试旧对象。

0.48.6 的批量前缀转发补丁没有覆盖此连接生命周期缺陷。初次连接中断的现场诱因仍未知；AMQP 504 不等同于 HTTP 网关超时。

## 修复

- 增加运行期 Session：通道/连接关闭时重建连接、通道和独立的 Publisher 确认状态；操作失败或超时丢弃旧连接，下次工作重试重新连接。
- 覆盖边缘上传读取/发布、边缘下发读取、边缘 CDC 发布、中心入口读取/转发、中心 replay 发布、中心 CDC 下发。
- 整个读取批次固定在同一个通道实例上；消息 ACK/NACK 仍引用收到消息的原通道，不能用新通道确认旧 delivery tag。
- 不在底层把失败发布改成成功或隐式重发。确认未知时返回失败，上层仍按原 RabbitMQ NACK/Canal 不提交位点重试。重复投递保留同一 event_id，由既有 Apply 幂等处理。
- 连接/握手预算 5 秒，心跳 5 秒，单次 Session 操作预算 15 秒；停止或超时会关闭当前连接，避免永远等待确认。重试沿用配置的 retry_interval_seconds。批次/积压大小与网络状况会影响全部追平时间，不承诺任意积压都在固定时间清空。
- 诊断 WorkerStatus 新增 consecutive_errors，成功处理或成功空闲探测后归零；last_processed_at 不因空闲/重连而伪造新成功时间。日志区分 transport reset、reconnect failed、worker recovered。进程 running 仍只代表进程状态。

无新增业务表、字段、规则变化或系统迁移。安装沿用已有 upgrade-system，校验系统迁移并记录 0.48.7；保留配置、规则、ACTIVE 对齐证明和 0.48.6 批量修复。
