## 修复与使用边界

1. 边缘账号补齐首次对齐所需默认交换机写权限及限定对齐队列 configure/read 权限。已有账号升级后需重新调用配置边缘账号入口；外部 RabbitMQ 需管理员更新权限。
2. 旧计划仍绑定旧目标库，之前同 ID 重用计划会报 `alignment_rule_changed`。现在在写拓扑前诊断旧/新计划冲突，并提供可执行的新一代迁移流程，不删除旧作业、证明、行版本或墓碑。
3. 新增 MCP `nodebridge_plan_rebaseline`、`nodebridge_prepare_rebaseline`，支持整组更换双向规则 ID、库表、主键和列映射。新规则在新系统库中重新对齐；已知旧 epoch 消息通过原证明核验后记审计，不再覆盖新基线。
4. 以 Edge 为权威源（此次用户指定 105）。目标整表先事务备份再清空，旧系统库保留。SQL 收据与本地恢复文件支持重复提交同一计划；部分准备或任一规则未对齐时阻止 Agent 启动。
5. 仅支持单 Edge/Server、离线维护。目标表需 InnoDB/主键，无触发器或关联外键；不支持多边缘迁移、在线修改或自动合并双方原数据。业务写入暂停由操作者完成，不自动停止业务服务。

普通规则保存继续保留旧证明保护。变更计划需执行专用 MCP 流程；本版没有新增图形迁移向导。只改显示名称仍可直接保存。
