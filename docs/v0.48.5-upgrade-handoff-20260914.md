# 0.48.5 中文规则名称与系统数据库升级

## 使用

升级包：`build/NodeBridge-beta-v0.48.5-20260914.exe`。在各参与节点停止同步并显式退出旧程序后运行安装包，保留本机已有配置、规则及账户。选择“复用现有组件”也会执行 NodeBridge 系统数据库升级，不需要重装 MySQL/RabbitMQ/Canal。

安装包 340902241 字节，SHA256 `4C8695C296CD1CBF414C3D41493584EE9B2E01598B23D70633B819C2352342A8`。包内 Agent SHA256 `BD3ECC8ACC1C217484D2BD7E5C001FE9615A749F79196C091196C6B727DD580A`，与真实升级验证及 MCP 检查使用的程序一致。安装包未签名；解包 62 文件、20 个系统迁移和 5 个依赖资产逐项哈希通过，证据 `.cache/v0485-release/package-gates.json`。

升级后在规则页填写“规则名称”，例如“检测标准双向同步”。名称在左侧列表及详情顶部优先突出显示，原规则 ID 以较小文字辅助查看；已保存 ID 只读。原 31 条规则可以直接填写中文名称，不需要删除重建或重新首次对齐。未填写名称时回退显示原 ID。

## 名称与兼容

- `SyncRule.name` 为可选显示字段，随现有 YAML 配置和 Wails/MCP DTO 保存；规则的运行身份仍为 `id`。没有将 YAML 和数据库做成两套可编辑名称来源。
- 改名称不会改变对齐计划的规则哈希、ACTIVE 证明匹配或 Agent 运行语义版本；旧无名称规则、原对齐记录继续有效。完整配置仍执行 CAS，真实业务映射/方向/ID 变化继续受原校验保护。
- 界面名称为 15px 加粗标题，ID 为 11px 辅助文字。中文、英文、日文均支持名称输入和搜索，窄屏规则选择框同样优先显示名称。

## 安装时更新数据库

安装器在恢复 UI 前执行 `SyncAgent.exe upgrade-system -config <现有配置> -allow-unconfigured`，从配置读取本机 `edge/server` 角色以及 MySQL 系统库，使用包内对应角色的迁移文件。

- 检查/补齐既有 `sync_*` 系统表与诊断索引；跳过最早初始化脚本里的示例业务表。没有给用户业务表新增列或修改原数据。
- `sync_schema_migration` 记录已完成迁移的文件校验值、应用版本和时间；`sync_schema_version` 在全部升级步骤成功后记录本机角色、版本和时间。
- 同一配置的同步进程必须停止；系统库迁移使用数据库互斥锁。已有迁移校验值不同、连接/权限或迁移失败都会报告错误，安装不会继续恢复 UI 或报告成功。成功迁移可重复执行，失败步骤可排障后重试。
- 新装且尚未填写节点及数据库时，明确记录 `not_configured/skipped`，不伪称数据库已更新。完成配置后可执行 `SyncAgent.exe upgrade-system -config <现有配置>`。已配置但不完整或无法连接时会失败，不静默跳过。
- 日志保留于 `%ProgramData%/NodeBridgeInstallerLogs/<本次运行>/`，包含 `system-database-upgrade.json` 和安装摘要。没有自动解除、删除或重建任何首次对齐账本。
