## 本机怎么安装

先备份 `C:\ProgramData\NodeBridge`，在原管理入口停止工作区Agent、退出旧UI，确认旧副本结束。本轮只出包，未执行这些现场操作；交付时旧Agent仍为PID15972，路径仍是0.46.13工作区，不把该PID当作未来实时值。

双击0.46.15，在新增的“组件安装方式”页保持默认：**复用现有组件（Docker / 已有服务，默认）**，继续安装。当前本机MySQL3306、RabbitMQ5672、Canal11111均为Docker服务，配置已是server-001及external，适用此模式。

仅全新且确实需要Windows原生组件的环境选择“安装本机系统组件（全新环境）”。已有边缘组件正常运行时，升级也可选择复用。MySQL不会由本安装包安装。

| 模式 | 行为 |
| --- | --- |
| 复用，默认 | 更新NodeBridge；跳过Erlang/RabbitMQ/Java/Canal安装、受管密码迁移和组件拓扑配置；已有配置及规则原文保留，已有密码不改。 |
| 复用，首次安装 | 配置不存在时写入external bootstrap，节点身份/库/凭据仍须配置；不自动发现Docker或验证连接。 |
| 安装本机系统组件 | 显式执行既有原生组件安装及受管配置流程；仍有试用版1234密码迁移约定，需明确确认环境归属及端口。 |

复用不会把已有managed配置自动改成external，不清理或改写原有组件归属清单。该选择只控制本次安装；后续在UI/MCP手动修改受管配置仍按其原有权限执行。新装默认管理/退出密码仍为1234，内网试用边界不变。

## 命令行

无参数交互或 `/S` 静默安装默认均为复用。兼容 `/SkipSystemComponents`，显式安装组件改用 `/InstallSystemComponents`。两者同时传入时在安装前拒绝并返回2。

直接运行 `install.ps1` 也默认复用，需显式 `-InstallSystemComponents` 才安装组件；两开关冲突即失败。原先依赖无参数自动安装组件的部署脚本必须更新。这是安全默认值的明确变更，不是自动Docker检测。

## 边界

交付的是用户允许的**半自动选择模式**，未实现自动Docker发现、端口归属推断或连接探测。未重新在真实空白VM安装原生组件；该路径为保留实现加fixture调用验证。没有安装到本机/边缘、没有停止Docker或现有Agent、没有修改业务规则和数据，也未启动长测。FB-094完整长测复验、FB-084真实UI恢复、FB-089时间字段误脱敏仍open。
