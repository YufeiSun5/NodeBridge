# NodeBridge v0.46.5 Real Edge-to-Server Stress Report

Date: 2026-09-08

## Scope

- Edge: `192.168.10.105`, installed NodeBridge v0.46.5, node `edge-001`, MySQL 8.4.
- Server: `192.168.10.103`, NodeBridge v0.46.5 simulation process, Docker MySQL 8.0.38, RabbitMQ and Canal.
- Path: remote MySQL -> Canal -> Edge RabbitMQ -> Server RabbitMQ -> Server Apply -> center MySQL.
- Rule: `nb_e2e_probe`, `EDGE_TO_SERVER`, `append_only`.
- Isolation: every tier used a dedicated BIGINT primary-key range; historical rows were excluded from assertions.

- Center rows: `20,000`.
- Apply logs: `20,000`.
- Recovery time: `35.216 s`.
- Recovery rate: `567.92 rows/s`.
- Final ingress depth: `0`.
- Server Agent remained running as PID `51540`.

## Residual Coverage

This run validates a single real Edge, append-only INSERT pressure, bounded Server downtime, and exact recovery. It is not a multi-edge concurrency test, an UPDATE/DELETE contention test, or an overnight soak. The 81,000 evidence rows remain in the dedicated `nb_e2e_probe` ranges; they were not deleted because source-side DELETE is intentionally invalid for an `append_only` rule.
