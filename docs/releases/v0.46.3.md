# NodeBridge v0.46.3 Beta

本版用于 Windows x64 内网现场测试，保持 v0.46.2 的安装和 MCP 能力，并修复脱敏凭据测试与配置生效流程。

## 安装包

- 文件：`NodeBridge-beta-v0.46.3-20260907.exe`
- SHA256：`DD6852F3BA87550C8C1C708A52B8507875562E322EA3FE114DB4B8A6CAB1D6F9`
- 平台：Windows x64
- 包含：NodeBridge、SyncAgent、Erlang/OTP、RabbitMQ、Java Runtime、Canal、WinSW
- 不包含：MySQL

## 变化

- 修复 UI 将 `******` 当成 MySQL/RabbitMQ 真实密码进行连接测试的问题。
- 实验室 MCP 的 `nodebridge_save_config_patch` 支持可选 `restart_agent:true`，保存后立即重启 SyncAgent。
- 全新安装只写入空白引导配置：不预设 MySQL 用户、密码、数据库或同步规则；Log Web 默认关闭。
- NodeBridge 解锁密码、退出密码和 NodeBridge 自有 RabbitMQ 用户密码统一为 `1234`。
- 托管 RabbitMQ 用户名按 `node.id` 自动生成：边缘本机为 `nb-<node.id>-local`，连接中心为 `nb-<node.id>`；中心本机为 `nb-server-sync`。
- MCP 保存托管 RabbitMQ 配置时，先修改本机 RabbitMQ 服务用户，再保存配置，避免配置与服务密码不一致。
- 中心端可用 `nodebridge_ensure_server_edge_user` 按边缘 `node.id` 创建或迁移中心 RabbitMQ 用户。
- 升级安装保留已有 MySQL、Canal 和同步规则，同时迁移旧版 NodeBridge 解锁/退出密码以及托管 RabbitMQ 配置和服务用户密码。
- 覆盖安装会在复制文件前停止安装目录内正在运行的 NodeBridge/SyncAgent，避免旧 EXE 被占用导致升级失败；不会停止其他目录中的同名进程。

## 覆盖安装验证

`scripts/test-nsis-upgrade.ps1` 已执行真实两轮 NSIS 安装：第二轮开始前由同名 `SyncAgent.exe` 持续占用旧文件，安装器成功停止旧进程并覆盖 NodeBridge/SyncAgent，同时保留 ProgramData 中已有配置字段和规则文件。证据目录：`.cache/nsis-upgrade/20260907-174024-917/`。

## 安全说明

`1234` 仅适用于当前隔离内网试用要求，不适用于公网或正式生产部署。MySQL 不属于 NodeBridge 安装器管理范围，安装器不会预设或修改 MySQL 凭据。
